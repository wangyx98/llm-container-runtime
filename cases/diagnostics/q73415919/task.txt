A Kubernetes node runs RKE2, and its containerd (the CRI runtime) cuts long log lines of containers into several records: a container that writes one line of about 60,000 characters in a single write gets that line as several partial records ("P") in its CRI log file, then the last one ("F"). The limit is containerd's max_container_log_line_size, 16384 by default. Raise it so that a line of up to 65,000 characters is stored as one record.

The node is a lab stand-in for RKE2 and is controlled like one: the RKE2 data directory is /var/lib/bench73415919/rancher/rke2, and the containerd configuration lives in /var/lib/bench73415919/rancher/rke2/agent/etc/containerd. RKE2 writes config.toml there again at every start ("File generated by rke2. DO NOT EDIT. Use config.toml.tmpl instead."); if a file config.toml.tmpl exists beside it, RKE2 renders that file and the result is the configuration, and in this stand-in the only template syntax it knows is the line {{ template "base" . }}, which stands for the default configuration. The command bash /tmp/bench73415919/restart-rke2.sh does what an RKE2 restart does to containerd: it renders config.toml, stops containerd and starts it again, and prints the end of the log when containerd does not come up. The containerd version is the one installed on this machine (containerd --version); its CRI plugin and the table of its settings are the ones of that version, so check where the setting lives in the generated config.toml.

The change must be made the way RKE2 keeps it, so that it survives a restart of the node, and it must work for both streams: after it, one write of a line of up to 65,000 characters to stdout, and the same to stderr, must be one record, "F", whose text is the line as it was written. A line longer than the new limit must still be stored legally, as partial records and an end record that join back to the line.

Allowed: the standard shell tools, sudo, and the restart command above. Do not stop at editing a number in a file: the check runs real containers through the CRI of this containerd, before and after a restart of the node, and compares what is in their log files. Do not change the lab's files under /tmp/bench73415919 (the restart script, its default configuration) and do not install or replace containerd.

The current user has passwordless sudo. Unless stated otherwise, assume container-runtime commands need sudo.

Return the commands needed to complete the task.
