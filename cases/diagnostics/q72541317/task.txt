Docker has "docker manifest inspect"; the containerd on this machine, which has no registry to ask, holds images that were imported offline and nothing at hand shows their manifests. Write a command that shows the manifest of an image of this containerd, the stored one.

The containerd listens on /run/bench72541317/containerd/containerd.sock (not the default socket); work in its default namespace only. Two images are in it: bench72541317.local/app:1, a multi-platform image (linux/amd64, linux/arm64 and linux/arm/v7: its top-level content is an index, a manifest list), and bench72541317.local/solo:1, a single-platform image (linux/arm64: its top-level content is a manifest, there is no index). Other images exist on the machine; the command must work for any image of the default namespace, including images imported after you finish, and for either kind of image, whichever media types (OCI or Docker) they use.

Create the bash script /tmp/bench72541317/inspect-manifest.sh (it is run with bash) that takes three arguments: IMAGE, the name of the image as ctr images ls shows it; PLATFORM, like linux/arm64 or linux/arm/v7 (operating system, architecture, and a variant when there is one); and OUTDIR, a directory (it may not exist: the script creates it). It writes, byte for byte as they are stored in containerd's content store (the sha256 of the bytes is the digest of the blob): OUTDIR/index.json, the image's index, only when the image is a multi-platform image; and OUTDIR/manifest.json, the manifest of PLATFORM (for a single-platform image: its manifest). It prints on its standard output these lines, each a keyword, a space and a digest (sha256:...) and nothing else on the line: index (only for a multi-platform image), the digest of the index blob; manifest, the digest of the manifest blob; config, the digest of the config blob that this manifest names (the image ID, which is not the digest of a manifest or of an index). It exits with a non-zero status, and writes no manifest.json, when the image or its platform does not exist. It must not change anything in containerd (no import, no tag, no delete, no pull). Afterwards, run it for bench72541317.local/app:1 and linux/arm64.

Allowed: the standard shell tools, python3, sudo, and containerd's own client ctr, the content store of this containerd. Do not use Docker or nerdctl, and nothing that needs a registry or the network.

The current user has passwordless sudo. Unless stated otherwise, assume container-runtime commands need sudo.
