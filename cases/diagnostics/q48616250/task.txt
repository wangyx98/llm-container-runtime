A node runs one containerd, on its own socket /run/bench48616250/containerd/containerd.sock (it has the CRI plugin), and a Docker daemon, whose API socket is /run/bench48616250/docker.sock (it belongs to the group of the current user: docker -H unix:///run/bench48616250/docker.sock ps works without sudo). The Docker daemon is configured to use that same containerd. The node also has a Kubernetes-style pod, run through the CRI of that containerd (the CRI client crictl is installed but not configured: it needs --runtime-endpoint and --image-endpoint, both unix:///run/bench48616250/containerd/containerd.sock). Nobody explains why "docker ps" shows containers that "crictl ps" does not, why "crictl ps" shows containers that "ctr containers list" does not, and why "ctr containers list" shows nothing at all.

Each of the three clients talks to its own API and shows the objects that API keeps. containerd keeps its objects in namespaces (a containerd namespace is a label that separates the clients of containerd; it has nothing to do with a Linux namespace, nor with the Kubernetes namespace in which a pod lives, which is a label of the pod). "ctr" works in one containerd namespace at a time, "default" unless told otherwise. Docker and the CRI plugin each use a containerd namespace of their own. A pod sandbox is a container of containerd too, but it is a pod to the CRI, not one of its containers; "docker ps" and "crictl ps" without -a list the running containers only.

Create the bash script /tmp/bench48616250/list-containers.sh (it is run with bash) that takes one argument, the path of an output file, and writes into it one JSON object that says, for each API, what it lists and where that lives:
- docker: an object with socket (the socket of the Docker API), containerd_namespace (the containerd namespace in which Docker's containers live) and containers (the array of the full IDs that "docker ps -a" lists);
- cri: an object with socket (the socket of the CRI), containerd_namespace (the containerd namespace in which the CRI plugin keeps its containers and sandboxes), kubernetes_namespace (the Kubernetes namespace of the pod, as the CRI reports it), containers (the array of the full IDs of the containers that "crictl ps -a" lists) and sandboxes (the array of the full IDs of the pod sandboxes that "crictl pods" lists);
- ctr: an object with socket (the socket ctr talks to) and namespaces (an object with one key for every containerd namespace that "ctr namespaces ls" shows and also the key default; the value of a key is the array of the container IDs that "ctr -n NAME containers list" shows in that namespace, which is empty for default).
The order of the arrays does not matter. The script only reads: it must not create, start, stop, kill, remove or prune any container, pod or image, move anything from one API to another, or change the daemons. It will be run again later, after the state of the node has changed (containers started and removed), so it cannot hold a copy of today's output. After creating it, run it with the output file /tmp/bench48616250/containers.json.

Allowed: the standard shell tools, python3, sudo, docker (with the -H above), crictl and ctr. Do not use nerdctl.

The current user has passwordless sudo. Unless stated otherwise, assume container-runtime commands need sudo.

Return the commands needed to complete the task.
