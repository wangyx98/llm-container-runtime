On this shared Ubuntu machine a small container node is modelled on the question "jdk vulnerability displaying in containerd overlay snapshot": a security scanner reports java-1.8.0-openjdk in directories below the snapshotter's directory of containerd, and the platform team wants to know from which image each of them was made (and what the complete Dockerfile was). `ctr container list` and `ctr snapshot ls` show nothing.

The node is a private containerd 1.7.20 (socket /run/bench77179505/containerd.sock; its files are below /var/lib/bench77179505 and /run/bench77179505; the machine's own containerd and ctr are not the node's) with the overlayfs snapshotter, which keeps its snapshots in /var/lib/bench77179505/containerd/io.containerd.snapshotter.v1.overlayfs/snapshots/N/fs (N is a number). The commands are /var/lib/bench77179505/bin/nodectl start|stop|restart|status and /var/lib/bench77179505/bin/ctr (ctr for the node's socket; give it -n NAMESPACE), both with sudo; python3 is on the machine. The node has no CRI plugin and runs nothing: it holds images, snapshots and container records. Nothing has to be pulled from the internet, and the node's garbage collection does not run.

The scanner's finding is the file usr/lib/jvm/java-1.8.0-openjdk/release (below N/fs). Your task: write a read-only report, /var/lib/bench77179505/out/report.json, of every directory N that holds that file, saying what the directory is and what it belongs to. It is a JSON object:
  {"snapshots": [ {"dir": "N", "namespace": "...", "kind": "layer" or "active", "key": "...", "images": [...], "containers": [...], "unreferenced": true or false}, ... ],
   "dockerfile": {"status": "unrecoverable", "history": {"IMAGE DIGEST": ["created_by line", ...], ...}}}
 - dir: the number N, as a string. namespace: the containerd namespace the snapshot belongs to (every namespace of the node has to be looked at; the same layer imported into two namespaces is two snapshots in two directories).
 - kind "layer": a committed snapshot, the unpacked layer of images; key is its snapshot key; images are the digests (sha256:..., the digest of the image as `ctr images ls` shows it, the manifest) of ALL the images of that namespace that have this layer among their layers, whatever their names; a layer shared by two images is one snapshot with two images; containers is empty and unreferenced false.
 - kind "active": a writable layer (the upper layer of a container, or one that nothing uses any more); key is its snapshot key; containers are the IDs of the containers of that namespace that use it as their snapshot (none: unreferenced is true, otherwise false); images are the digests of all the images of that namespace whose layers contain its parent snapshot.
 - dockerfile: an image does not keep its Dockerfile, so it cannot be recovered: status is "unrecoverable", and history has an entry for each image digest named in snapshots, the created_by lines of the history in that image's config, in order, exactly as they are. Do not write a Dockerfile of your own.

The report is made from what the node knows (ctr and the files of the snapshotter), by a script that finds the directories itself; the result is what is checked. Leave the node as it is: do not remove, change or add any snapshot, image, container or label (a temporary snapshot made for the work has to be removed again before you finish), and do not touch the lab's files (the programs, the configuration, the tools in bin).

The current user has passwordless sudo. Unless stated otherwise, assume container-runtime and system commands need sudo.

Return the commands needed to complete the task.
