A host runs MicroK8s. MicroK8s has its own containerd, on its own socket: /run/bench61055917/containerd/containerd.sock (the command microk8s.ctr is ctr with that socket). The host has a second containerd socket, /run/bench61055917/docker/containerd.sock, which belongs to something else and is not part of this node: it must not be connected to at all. There is no Docker CLI and no kubectl to use. An administrator ran "ctr containers ls" and "ctr images list" against the MicroK8s socket and both listed nothing, although the node runs workloads. containerd keeps its objects in namespaces, and ctr works in one namespace at a time ("default" unless told otherwise). A container of containerd has an image; its task is the process that runs it, which a container may not have (one here was created and never started). The administrator wants, for this node, every container with the image it uses, the digest of that image and the PID of its process, and every image of the node with its digest (containerd's CRI plugin also lists each image a second time under its bare ID, a name of the form sha256:...; those entries may be listed or left out). "ctr containers ls" shows neither the digest nor the PID: the digest of an image and the process IDs of the tasks are in other ctr listings. Two images can have the same name and tag in different registries, with different digests, and an image may be used by no container.

Create the bash script /tmp/bench61055917/list-node.sh (it is run with bash) that takes one argument, the path of an output file, and writes into it one JSON object with two arrays:
- containers: one object for every container of the MicroK8s containerd, with the keys id (the container ID), image (the image name, as ctr shows it for the container), digest (the digest of that image, sha256:..., as ctr shows it for the image) and pid (the PID of the container's process on the host, as an integer, or null when the container has no task);
- images: one object for every image of the MicroK8s containerd, with the keys ref (the image name) and digest (sha256:...), whether or not a container uses it.
The order of the objects does not matter. The script only reads: it must not pull, import, tag, remove or label an image, create, start, stop, kill or remove a container or task, or create a namespace. It will be run again later, after the state of the node has changed (a task killed or started, new images and containers), so it cannot hold a copy of today's output. After creating it, run it with the output file /tmp/bench61055917/node.json.

Allowed: the standard shell tools, python3, sudo and ctr. Do not use Docker, nerdctl or crictl.

The current user has passwordless sudo. Unless stated otherwise, assume container-runtime commands need sudo.

Return the commands needed to complete the task.
