On this shared Ubuntu machine a docker daemon of its own, separate from the host's docker, runs one container named web; it is reached with DOCKER_HOST=unix:///run/bench45937714/src.sock (for example "sudo docker -H unix:///run/bench45937714/src.sock ps"). The container was started long ago with a docker run command that nobody has kept. It runs an HTTP service on 127.0.0.1:18437 (published to port 8080 in the container) that answers with lines nonce=, mode=, extra=, title=, workdir=, conf=, data= and marker=: the first lines come from the container's environment and arguments, conf= is the content of the file /etc/app.conf, data= is the size and a checksum of the file /data/records.bin and marker= is the content of the file /var/lib/marker.txt.

The problem: the daemon's machine is going to be lost, and the container has to be backed up in a way that it can be brought back on a new, empty docker daemon without anyone knowing the original docker run command. Saving the image is not enough: the container's configuration (command and arguments, the environment variables NONCE, APP_MODE and EXTRA, the working directory, the label bench.role, the restart policy and the published port), the named volume webdata mounted on /data, the file mounted read-only on /etc/app.conf from the host, the file /var/lib/marker.txt that was written into the container's own writable layer, the user-defined network appnet that web is attached to with the network alias web-svc, and the fact that it runs, all belong to the container. The host's file that is mounted on /etc/app.conf will be gone with the machine.

Your task is to create the backup in the directory /var/backups/bench45937714 so that the container can be brought back from that directory alone. The directory must contain an executable script restore.sh, together with whatever files it needs. The check will delete web, its volume, its network, its image and the whole daemon with the host's configuration file, copy your backup directory to another place, start a new docker daemon with nothing in it (no image, no volume, no network of web) and run "bash restore.sh" there as root, with the copy of the backup directory as the current directory, with a clean environment in which DOCKER_HOST is the only pointer to the new daemon (do not hard-code a socket and do not rely on anything outside the backup directory and the standard tools). Then it checks, on the new daemon, that web runs with the same command, environment, working directory, label, restart policy, published port, volume, read-only file mount and network alias, that the service on 127.0.0.1:18437 answers exactly as it answers now (the same nonce, the same data, configuration and marker), and that the same holds after "docker restart web".

Rules: the backup must not stop, replace or change web on the old daemon (it has to keep running while you make the backup and afterwards), and nothing may stay running on the host that answers on port 18437 instead of the restored container. Use docker, tar, python3 and the standard shell tools; the docker CLI needs sudo and DOCKER_HOST.

The current user has passwordless sudo. Unless stated otherwise, assume container-runtime and system commands need sudo.

Return the commands needed to complete the task.
