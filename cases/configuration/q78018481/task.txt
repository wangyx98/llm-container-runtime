This machine runs containerd (no Docker daemon, no CRI-O) with the CRI plugin enabled; Kubernetes pods are created through the CRI. containerd is started and stopped with a script, /var/lib/bench78018481/bin/containerdctl (start, stop, restart, status; run it with sudo). containerd reads its configuration, /run/bench78018481/config.toml (owned by root), only when it starts, and its socket is /run/bench78018481/containerd.sock. The CRI client is crictl; point it at that socket:

Every pod sandbox runs a "pause" image, the sandbox image of containerd. Today containerd takes it from this registry (plain HTTP, already usable by containerd's CRI):

    127.0.0.1:18081/google_containers/pause:3.6

A second registry (plain HTTP as well, also already usable by containerd's CRI) holds the same version of the pause image, a valid one that is not the same image (its digest is different):

    127.0.0.1:18082/google_containers/pause:3.6

The team wants the sandbox image to be downloaded from the second registry from now on. A pod, bench78018481-old, is already running with the pause image of the first registry.
