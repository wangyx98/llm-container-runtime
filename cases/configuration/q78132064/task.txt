This machine runs containerd (no Docker daemon, no CRI-O) with the CRI plugin enabled. It is started and stopped with a script, /var/lib/bench78132064/bin/containerdctl (start, stop, restart, status; run it with sudo). containerd reads its configuration, /run/bench78132064/config.toml (owned by root), only when it starts, and its socket is /run/bench78132064/containerd.sock. The CRI client is crictl; point it at that socket:

    sudo crictl --runtime-endpoint unix:///run/bench78132064/containerd.sock --image-endpoint unix:///run/bench78132064/containerd.sock pull ...

The Kubernetes workloads of this machine use images from Docker Hub by their usual names, for example docker.io/library/benchapp:1.0. This machine has no route to Docker Hub: everything containerd sends to the Internet goes through an egress gateway that refuses it, and every refused connection is logged. That is why the team set up a Nexus Docker proxy repository for Docker Hub. It listens on 127.0.0.1:8082 (plain HTTP, no TLS), allows anonymous pull, and already caches the image library/benchapp:1.0 (as Nexus names it, official images live below library/). In this test environment the Nexus proxy is a stand-in server that speaks the same registry API; it is not the Sonatype Nexus product.

containerd has no registry configuration for the CRI yet, so it still goes to Docker Hub:

    $ sudo crictl --runtime-endpoint unix:///run/bench78132064/containerd.sock --image-endpoint unix:///run/bench78132064/containerd.sock pull docker.io/library/benchapp:1.0
    FATA[0000] pulling image: failed to pull and unpack image "docker.io/library/benchapp:1.0": failed to resolve image: failed to do request: Head "https://registry-1.docker.io/v2/library/benchapp/manifests/1.0": Forbidden

Your task: change the default image registry of this machine's containerd, for the CRI, from Docker Hub to the Nexus proxy, so that the images keep their names (docker.io/library/benchapp:1.0) and are pulled through the proxy.

Requirements:
