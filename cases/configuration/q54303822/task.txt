Two containers of the same image are running: bench-api and bench-batch. Each has its own environment variable BENCH_TOKEN, its own read-only bind mount on /data, its own hostname, memory limit and CPU limit.

You want to start the same container again with runc, outside Docker, and for that you need the OCI runtime spec, the config.json, that runc was started with for the running container bench-api. The places named on the web for it (for example /run/docker/libcontainerd/<id>/config.json, /var/run/docker/libcontainerd/<id>, /var/run/docker/containerd/daemon/io.containerd.runtime.v1.linux/moby/<id> and /run/containerd/io.containerd.runtime.v1.linux/moby/<id>, where <id> is the container id) do not exist on this engine: where the file is depends on the versions of Docker, containerd and runc. The check reads the saved file and accepts it only if it is the real thing: it must be identical to the config.json that runc was started with for bench-api and be the spec of that container (its BENCH_TOKEN, hostname, read-only mount on /data, memory limit, CPU quota and cgroup are compared with Docker's object, with the running process and with its cgroup).
