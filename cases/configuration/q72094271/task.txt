In any container, "ulimit -c" prints unlimited, both in its main process and in a process started with "crictl exec", and a process that dies of SIGABRT leaves a core file. Putting "ulimit -c 0" into the Dockerfile of an image and a limits.conf with "core 0" lines into the pod did not change it.

Your task is to restrict the core file size to 0 for every container this node creates from now on, in its main process and in every process started in it with exec, as soft limit and as hard limit (a process must not be able to raise it again), for all pods and not for one of them, and so that this is still true after the service has been restarted. The check removes every pod, creates new pods in the host's network namespace with crictl, reads /proc/PID/limits of the main process of their containers, runs probes with "crictl exec", lets processes die of SIGABRT and looks for core files; then it restarts the service with "systemctl restart bench72094271-containerd.service" (it does not run any other systemctl command first) and does the same with new pods.
