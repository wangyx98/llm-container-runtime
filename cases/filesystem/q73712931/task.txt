On this shared Ubuntu machine a small node is modelled on the question "containerd - image might be filtered out message": an image saved with docker save on another machine (pulled from quay there) is carried to an offline host, and `ctr images import` of the archive on containerd 1.6.8 says "image might be filtered out", while containerd 1.5.13 says that a content digest is not found; the answers guess at a platform filter, an archive that is not complete, or a version difference, and `--all-platforms` does not give back blobs that are not in the file. What follows is an adaptation: no quay and no network at all; a private containerd 1.6.8 (no CRI plugin) with runc 1.1.12, and the archives are on disk.

The node lives below /var/lib/bench73712931 (programs in node/bin, containerd's root in containerd) and /run/bench73712931; `sudo /var/lib/bench73712931/bin/nodectl status` shows it. The wrapper `sudo /var/lib/bench73712931/bin/ctr ...` talks to this node and to no other (namespace default unless -n is given; `ctr ... run` keeps runc's state in the node's own directory). Two archives of the application image bench73712931.local/app:1 are in /var/lib/bench73712931/archives: app-foreign.tar, the asker's kind of file (a docker save: manifest.json, one config, one layer), and app-multi.tar (an OCI layout: index.json, an index with one manifest per platform, blobs/sha256/...). The image's program prints "marker " and a token that is in its layer. Nothing is imported yet.

Your task has two parts.

1. Write the tool /var/lib/bench73712931/archreport (an executable run with sudo, with ONE argument: the path of an archive, any path, spaces possible). It reads only that archive (a tar; it will be run later on other archives of the same kind: a docker save, or an OCI layout with an index of per-platform manifests, whole or with blobs left out) and prints ONE JSON object on stdout:
- "format": "docker-classic" (manifest.json) or "oci-layout" (index.json); "name": the image name (RepoTags[0] of the docker save; for the OCI layout the annotation io.containerd.image.name of index.json); "host_platform": "linux/amd64" or "linux/arm64", the platform of this machine.
- "platforms": a list, sorted by platform, one object per platform of the archive: "platform" ("linux/<architecture>": the platform of the index entry; for a docker save, of its config); "manifest" (the digest of that platform's manifest, null for a docker save); "config" (the digest of its config: for a docker save the sha256 of the config file; null when the manifest is not usable); "layers" (the digests of its layers in order: for an OCI layout those of the manifest, for a docker save the diff_ids of the config; [] when the manifest is not usable); "missing" (the sorted digests that this platform needs and the archive does not have: its manifest, config and layers; a blob counts as missing also when it is in the file but its content does not hash to its name; when the manifest is missing, only the manifest).
- "missing_blobs": the sorted union of the platforms' "missing".
- "verdict": "importable" (the host platform is in the archive and none of its blobs is missing), "no_host_platform" (the archive has no image for the host platform), or "incomplete" (the host platform is there, a blob it needs is missing).
- "import_ok": whether `ctr images import ARCHIVE` on this node (a plain import, no flag) succeeds; "import_all_platforms_ok": the same with `--all-platforms`; "runnable_on_host": whether, after an import that succeeds (the plain one, else the one with --all-platforms), a container of the image really runs its program here (prints the marker) and does not fail to start.
These are compared with what the lab knows of the archives and with what this node really does with each of them (plain import, import with --all-platforms, a run of the image), for archives that the lab makes later with random contents. The tool must not change anything on the node (it imports nothing; the lab compares the content store, the namespaces, the image records and the snapshots before and after), needs no network, may not call docker, and must finish within 30 seconds.

2. Make the application usable here: the image bench73712931.local/app:1 must be in the namespace default of this node for this host's platform, taken from the archives in /var/lib/bench73712931/archives (no pulling, no network, the archives are not to be changed or removed), such that every blob it needs is in the node's content store with the content its digest says and `sudo /var/lib/bench73712931/bin/ctr run --rm bench73712931.local/app:1 NAME` runs its program and prints its marker. An image that was only imported (for example for another architecture) does not count as running.

The current user has passwordless sudo. Unless stated otherwise, assume container-runtime and system commands need sudo.

Return the commands needed to complete the task.
