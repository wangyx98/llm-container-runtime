A bind mount made on the host does not help. For example, after a bind mount of B onto a directory of A's root filesystem on the host (the directory where containerd keeps A's root, under /run/bench75052934/io.containerd.runtime.v2.task/k8s.io/), the host sees the files in there, but A's processes still see an empty directory: A's mount namespace is a private copy, and a mount made later on the host is not propagated into it. Changing the propagation of the host's mounts does not change that for a namespace that is already there. From inside A there is no way to see the host directory either, since A's root is its own image.
