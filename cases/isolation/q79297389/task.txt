A containerd node (no Docker daemon, no CRI-O, no nerdctl) runs a container named
"bench79297389-app" in containerd's namespace "k8s.io". It runs as an ordinary
user of its image (not root), and its main process has to keep running that way.
The host directory /tmp/bench79297389/data is mounted at /data inside it.

The image's program /usr/bin/maintain is a script of the kind the question
describes: it refuses to run unless the user that starts it is root, user id 0
AND group id 0. When it runs, it writes its result file /data/done (on the host:
/tmp/bench79297389/data/done) and prints a line.

You work on the node through its debug container, like `kubectl debug node/...`
followed by `chroot /host`: the node's own file system is the root there, with
containerd's socket, ctr, runc and the runc state directory
/run/containerd/runc/k8s.io at their usual paths. Anything you want to run in it
goes through the wrapper (run it with sudo):

    sudo /tmp/bench79297389/node-debug COMMAND [ARG...]

The debug container, its capabilities, its namespaces and its mounts are fixed.
Tried there as root, the attempts to get a process of the right user into the
container fail:

    $ sudo /tmp/bench79297389/node-debug ctr -n k8s.io task exec --exec-id x --user 0 bench79297389-app /usr/bin/maintain
    ctr: failed to unmount /tmp/containerd-mount...: ...: failed to mount /tmp/containerd-mount...: ...
    $ sudo /tmp/bench79297389/node-debug runc --root /run/containerd/runc/k8s.io exec --user 0 bench79297389-app /usr/bin/maintain
    ... nsexec-1: failed to open /proc/.../ns/ipc: Permission denied

Your task is to run /usr/bin/maintain once inside the running container
"bench79297389-app" as root (user id 0 and group id 0), so that it completes and
writes /data/done.
