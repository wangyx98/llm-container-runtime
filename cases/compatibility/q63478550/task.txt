Two private daemons run on this machine for this task, neither is the
Docker or the containerd of the machine:

- a containerd, with its socket at /run/bench63478550/containerd.sock (owned
  by root): use it with `sudo ctr -a /run/bench63478550/containerd.sock ...`;
- a Docker daemon, with its API socket at /run/bench63478550/docker.sock: use
  it with `sudo docker -H unix:///run/bench63478550/docker.sock ...`. This
  Docker has no bridge network, so its containers must be started with
  `--network none`.

Docker holds an image: `docker images` lists
registry.invalid/bench63478550/app:1. The image has a program as its
entrypoint, and a file /unique.txt inside, which the program prints. Docker
runs it fine. The containerd, which is what a Kubernetes node or any other
containerd user would use, has no image at all: `ctr images ls` is empty, and
`ctr run` of that name fails. The registry host registry.invalid does not
exist, so pulling the image from a registry is not possible, neither with
Docker nor with ctr, and there is no network to any other registry for it.

Your task is to make the very same image available to that containerd, so
that ctr can run it: Docker's images are not seen by containerd.

Requirements:

   `sudo ctr -a /run/bench63478550/containerd.sock run --rm registry.invalid/bench63478550/app:1 someid`
