This machine is a VM with systemd. It runs one container, web, made with runc directly (no Docker, no containerd). The engineer's runc is /var/lib/bench73434226/bin/runc (version 1.1.3); it keeps its state in /run/bench73434226/runc, and the container was started from the bundle /var/lib/bench73434226/bundle (config.json and rootfs) with:

    sudo /var/lib/bench73434226/bin/runc --systemd-cgroup --root /run/bench73434226/runc run -d --pid-file /run/bench73434226/web.pid web </dev/null >/dev/null 2>&1

so it runs as the systemd scope bench73434226-web.scope. Its process, /app (started with a token as its argument), writes one line with the time, its pid and the token to /data/heartbeat every second; /data is the host directory /run/bench73434226/data. The runc of the machine's own package is installed too (the runc on the PATH).

Right after the container was started, an interactive exec worked. Since a configuration reload of systemd (systemctl daemon-reload) it does not:

    $ sudo /var/lib/bench73434226/bin/runc --root /run/bench73434226/runc exec -t web /bin/sh
    ERRO[0000] exec failed: unable to start container process: open /dev/pts/0: operation not permitted

A non-interactive exec (exec web /bin/id) works, and the workload runs. A quick restart of the container made the interactive exec work for a while, until the next reload.
