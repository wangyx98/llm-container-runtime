Four machines of a small Kubernetes cluster are modelled on this shared Ubuntu host by four nodes, node1 to node4. Each node is a containerd of its own (own root, state, socket and configuration), started and stopped with /var/lib/bench77040211/bin/nodectl (nodectl start, stop, restart or status node1, node2, node3, node4 or all; it must run as root). The configuration of a node is /var/lib/bench77040211/<node>/etc/config.toml and its CRI socket is /var/lib/bench77040211/<node>/run/containerd.sock; a crictl for a node needs both endpoints, for example "crictl -r unix:///var/lib/bench77040211/node1/run/containerd.sock -i unix:///var/lib/bench77040211/node1/run/containerd.sock images". Docker cannot be installed next to containerd here, so the local image registry is the distribution registry run as a plain process: it listens on https://10.77.40.11:5000 (an address of this host that every node reaches) and holds the image argus. Its certificate is signed by the lab CA, /var/lib/bench77040211/pki/ca.crt. The pods of the application refer to the image by its digest: the reference is in /var/lib/bench77040211/argus.ref (the form is 10.77.40.11:5000/argus@sha256:...). The sandbox image of the pods, bench77040211.local/pause:1, is already in every node, so a pod needs nothing but its own image.

The problem: on every node "crictl pull $(cat /var/lib/bench77040211/argus.ref)", and so every pod that uses this image, fails with: failed to resolve image: failed to do request: Head "https://10.77.40.11:5000/v2/argus/manifests/sha256:...": tls: failed to verify certificate: x509: certificate signed by unknown authority (in Kubernetes: ErrImagePull, then ImagePullBackOff). The registry itself is fine: it is reachable from the nodes, the image and the digest exist, and a pull that is told which CA to trust works. What is missing is the configuration of the nodes' runtime.

Your task is to make all four nodes pull images from 10.77.40.11:5000 through the CRI (what the kubelet does), so that every node can pull the pinned image and run it. The check removes the image and its blobs from each node in turn, pulls the digest from /var/lib/bench77040211/argus.ref with the CRI and starts a pod with it that prints a fresh nonce; the registry's own log must show the requests of that node.

Rules: the registry must stay as it is (the same process, configuration and certificate; HTTPS at 10.77.40.11:5000, do not turn TLS off, move it or replace it); each node must stay the containerd that nodectl starts, with the configuration file of the node (do not change nodectl or the other files in /var/lib/bench77040211/bin, and the sandbox image must stay); do not change the certificate store of this host (/etc/ssl, /usr/local/share/ca-certificates, update-ca-certificates); and do not load the image into a node by hand (ctr images pull or import, docker), because the check removes it and pulls it again. Use nodectl, crictl, ctr and the standard shell tools; do not use docker, nerdctl, kubectl or kubeadm.

The current user has passwordless sudo. Unless stated otherwise, assume container-runtime and system commands need sudo.

Return the commands needed to complete the task.
