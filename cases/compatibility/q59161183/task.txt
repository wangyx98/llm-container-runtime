Your team builds container images with Docker on a build machine and ships
them to this host as tarballs written by `docker save`. On the build
machine, a locally built image is immediately usable by the local Docker
engine. This host is different: it runs the CRI-O container runtime (the
one Kubernetes/Minikube use in "cri-o mode"), and there is no Docker
daemon here at all.

One such tarball is already on this host:

    /tmp/bench59161183/app.tar

It holds a single image, tagged "bench59161183/app:local" by `docker save`.
Its entrypoint is a small long-running program that prints one line of
text per second. The image has never been pushed to any registry, so
there is nothing to pull it from.

Trying the obvious thing does not work: the image is not known to CRI-O,
and asking CRI-O to pull "bench59161183/app:local" ends with an error
because no registry has it. The same is true for any other
"just reference the local image by name" approach, because the images a
Docker engine keeps and the images CRI-O keeps are two completely
separate stores.

Your task is to get this image into CRI-O and run it there.

   "localhost/bench59161183/app:local", so that `sudo crictl images`

   SANDBOX_READY, and a container named "bench59161183" that belongs to
