This machine runs a single-node Kubernetes (k3s, node bench75845783-node) on a containerd of its own (no Docker daemon). containerd and k3s are started and stopped with the scripts containerdctl and k3sctl in /var/lib/bench75845783/bin (start, stop, restart, status; run them with sudo). The socket of this containerd is /run/bench75845783/containerd.sock, its data is below /var/lib/bench75845783/containerd. The same directory has two wrappers, which you run with sudo: kubectl (the kubectl of this Kubernetes) and nerdctl (nerdctl 2.1.3 of this machine, aimed at this containerd, namespace default; the CNI plugins v1.5.1 and the network configuration of its default network, bridge, are in /var/lib/bench75845783/cni).

An engineer wants to work with the containers of this node from inside a Pod. The Pod nerdctl-pod (namespace default, created from /var/lib/bench75845783/nerdctl-pod.yaml) is privileged and runs as root. It mounts the host's directory /var/run/containerd and the containerd socket of this node, on /var/run/containerd/containerd.sock. Its image bench75845783.local/nerdctl-pod:1 has nerdctl 2.1.3 at /home/linuxbrew/.linuxbrew/bin/nerdctl and a small shell toolset (sh, ls, cat, strace, ...); its environment variables CNI_PATH and NETCONFPATH name the CNI directories of the host, /var/lib/bench75845783/cni/bin and /var/lib/bench75845783/cni/net.d. The image of an application, bench75845783.local/app:1 (it prints its first argument every 5 seconds), is in this containerd, and a container, host-web, was started on the host with nerdctl.

In the Pod, nerdctl ps and nerdctl images work and show what was started on the host. nerdctl run does not:

    $ sudo /var/lib/bench75845783/bin/kubectl exec nerdctl-pod -- nerdctl run -d --name web2 bench75845783.local/app:1 hello
    time="2026-10-18T04:31:09Z" level=fatal msg="failed to mount {Type:bind Source:/var/lib/bench75845783/containerd/io.containerd.snapshotter.v1.overlayfs/snapshots/3/fs Target: Options:[ro rbind]} on \"/tmp/initialC419394580\": mount source: \"/var/lib/bench75845783/containerd/io.containerd.snapshotter.v1.overlayfs/snapshots/3/fs\", target: \"/tmp/initialC419394580\", fstype: bind, flags: 20481, data: \"\", err: no such file or directory"

The same command with the nerdctl wrapper on the host works.

Make nerdctl run -d work in the Pod nerdctl-pod itself. The Pod stays privileged and root, keeps its image and its two mounts, and must not get the host's root directory or the host's PID, network or IPC namespace. A container started by the Pod's nerdctl has to be a real container of this node's containerd (namespace default) on the default bridge network, like host-web: nerdctl ps in the Pod lists it and nerdctl logs in the Pod shows its output. Do not start the containers from the host in place of the Pod, and do not change the existing files of containerd, k3s, nerdctl or the CNI plugins on the host.

You may use kubectl, nerdctl, ctr, strace and the usual Linux tools. The current user has passwordless sudo. Unless stated otherwise, assume container-runtime and system commands need sudo. Return the commands needed to complete the task.
