trick like pointing the client at the cluster's daemon does not exist for it. This host plays both
roles, kept apart like a workstation and a Minikube VM would be:

  `sudo podman --root /tmp/bench59811664/workstation/root --runroot /tmp/bench59811664/workstation/run ...`.
  It holds one image, "localhost/bench59811664/app:v1". The image contains a file /etc/unique.txt

- The "cluster" is the CRI-O that runs on this host (endpoint unix:///var/run/crio/crio.sock, already

  the content of the file /tmp/bench59811664/registry.addr. It is empty at the start.
  Nothing sets up trust for it on either side. You may use it, or move the image another way.
