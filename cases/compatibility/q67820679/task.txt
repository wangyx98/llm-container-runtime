A containerd runs on this machine for this task (no Docker daemon, no CRI-O, no

A container called bench67820679-app is running in it, started by a colleague.
Its main process is a shell that loops forever, and it runs as the unprivileged
user 1234:1234. The container has the host's /usr (read-only, so that sh, id,

An engineer wants to run a command inside this running container, like
`docker exec` does. The container is up, but the engineer could not get into it:

    $ sudo ctr -a /run/bench67820679/containerd.sock containers ls

Your task is to run /probe.sh inside the running container bench67820679-app,
with ctr, so that /out/probe.txt (that is, /tmp/bench67820679/out/probe.txt on
the host) is written by the process that ran there.

Requirements:

1. The command must run INSIDE the container, started through containerd with
   ctr, as an exec into the task of the container. Running something on the

2. The process must run as the user the container runs as (do not change the

   task.

   stop, restart, delete or re-create it, and do not restart or reconfigure
   containerd.
4. /out/probe.txt must have been written by /probe.sh running in the container;
   do not write it yourself.
5. The script runs without a terminal: stdin is not a TTY, nothing can be typed.
6. The current user has passwordless sudo. Unless stated otherwise, assume
   container-runtime and network commands need `sudo`.
7. Your script must finish by itself: no interactive prompts, no command that
   runs in the foreground until it is interrupted, and no command that waits
   forever.
