# q76980610 — Configure Spring Boot Testcontainers to use containerd instead of Docker (compatibility) — DEFERRED

Status: analysed and deferred by the user (2026-11-01). Nothing was built (no case files, test suite, fixtures or docs-index entries).

## What the thread is about
Docker Desktop with "use containerd" enabled; a Spring Boot test that uses Testcontainers fails with `com.github.dockerjava.api.exception.DockerException: Status 502: Bad response from Docker engine`. The asker thinks the Docker daemon is disabled or unreachable, wants to point Testcontainers at containerd through `~/.testcontainers.properties` (`docker.host`, `docker.client.strategy`) and cannot find where Docker Desktop runs containerd; he also wants containerd in GitLab CI (a different problem). No answer. Two comments: (1) on Linux the socket is `/run/containerd/containerd.sock` (macOS differs because Docker runs in a VM); (2) the Testcontainers maintainer (Kevin Wittek): "Using Testcontainers with containerd image store in Docker Desktop works just fine".

## Reading of the thread
- The premise is confused: Docker Desktop's "containerd image store" only changes where the Docker engine keeps images; the Docker daemon and the Docker API stay. It does not mean "no Docker". The maintainer's comment says the setup works, so the 502 is not caused by needing containerd. The cause of the 502 is not determined (a Docker Desktop VM/socket-proxy state, or a Testcontainers/docker-java version issue); it cannot be reproduced on a Linux host without Docker Desktop.
- Comment (1) is wrong as a fix: `/run/containerd/containerd.sock` speaks gRPC, not the Docker HTTP API that docker-java speaks (the same protocol fact was measured elsewhere with Traefik's Docker provider against a containerd socket: `malformed HTTP response`; for Testcontainers/docker-java itself the exact error text was NOT measured).
