## What the thread is about
After `minikube addons enable gvisor`, the gvisor Pod is Running, but a Pod with the gVisor runtime class stays in ContainerCreating with `FailedCreatePodSandBox ... failed to set bridge addr: could not add IP address to "cni0": permission denied`. Disabling gVisor makes ordinary Pods work again. The only answer relays gVisor issue 7877: containerd changed its configuration format again; the addon still writes the old format and replaces the whole `config.toml`, losing the node's other settings; fixed in a later release. Neither the question nor the answer explains how that overwrite leads to the `cni0` EPERM.

## Measured on 2026-11-19 (sandbox x86_64, cgroup v1; containerd 2.4.2 and the 2.2.1 release binary)
- minikube v1.26.0 `pkg/gvisor/enable.go`: the addon downloads runsc from `releases/nightly/2020-02-14/runsc` and `containerd-shim-runsc-v1` v0.0.3 (amd64 only), copies the node's current config to `/tmp/config.toml`, REPLACES `/etc/containerd/config.toml` with the addon's own `gvisor-config.toml`, then `systemctl restart containerd` (via chroot /node, with rpc-statd stopped around it).
- That `gvisor-config.toml` (v1 schema, no `version` line): `root=/var/lib/containerd`, `state=/run/containerd`, `[plugins.cri]` with `sandbox_image = <repo>/pause:3.1`, `systemd_cgroup=false`, `default_runtime.runtime_type = "io.containerd.runtime.v1.linux"`, handlers `untrusted` and `runsc` (both `io.containerd.runsc.v1`), `[plugins.cri.cni]` bin_dir `/opt/cni/bin` and conf_dir `/etc/cni/net.d`, a docker.io mirror, `[plugins.linux] runtime="runc"`, no other node settings.
- containerd 2.4.2 and 2.2.1 load this file ("Configuration migrated from version 0"), ignore `default_runtime` and `no_pivot` and `systemd_cgroup` as unknown keys, and the CRI plugin comes up with runtimes `runc` (io.containerd.runc.v2, default), `runsc` and `untrusted` (io.containerd.runsc.v1) and the standard CNI directories. So on 2.x the real addon file does not by itself break the runsc handler or the network; the v1 default runtime is what the 1.6-era node tripped over.
